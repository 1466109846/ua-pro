# UA PRO

Magpie 的出站客户端兼容插件：**连接与凭据独立保存，Codex / Claude Code 规则以模板版本管理**。支持 Responses、Anthropic Messages、Chat Completions、Gemini。

当前版本 **0.3.6**。主供应商是 `ua-pro`，旧 `claude-code-ua` 保留为兼容入口。包定位暂保留 `opencode-claude-code-ua`，本地目录不变，不会擅自移动已安装来源。

## 开始使用

在 Magpie「插件 → 添加插件」填写 GitHub 来源：

```text
github:1466109846/ua-pro
```

终端也可以安装并登录：

```sh
magpie plugin add "github:1466109846/ua-pro"
magpie plugin login ua-pro
```

登录方式中选择 **打开 UA PRO 管理**。插件已内嵌日芒 SVG 图标，宿主无需联网获取图片。

如需独立运行管理页，可下载仓库或 Release 压缩包，在插件目录运行：

```sh
node setup.mjs
```

打开终端输出的一次性回环链接。独立工具保存连接后，在 Magpie 重载本插件，宿主会发现已保存的连接。设置服务不会默认监听公网。

界面采用**白天纯白、夜间纯黑**画布，中性灰边线与暖橙强调色；保留旧版 Claude 配置页的日芒 Logo 和本地状态侧栏。支持浅色、夜间及跟随系统，设置、卡片和表单统一间距，窄屏使用顶部导航。

客户端继续填写 Magpie 的本地网关地址、Magpie 网关密钥，选择实际供应商的模型引用。主池为 `ua-pro/<模型名>`；独立站点为 `ua-pro-<siteId>/<模型名>`，例如 `ua-pro-any/claude-fable-5-2`。测试页会显示可复制的实际引用，不能把独立站点模型写成主池模型。上游的 Base URL / API key 只填在 UA PRO 连接或 Magpie 原生账号中。不同客户端到目标 API 的协议转换由 Magpie 负责，UA PRO 接收转换后的请求并执行模板。

## 初始化模板

首次加载会幂等建立三条模板记录：

| 模板 | 类型 | 行为 |
|---|---|---|
| **Codex** | 内置只读 | Responses，参考 Sub2API 插件0.4.16的UA/身份头/元数据提升/稳定会话兼容 |
| **Claude Code** | 内置只读 | Messages，参考2.1.296 CLI UA、条件性system/user_id补全、fast beta联动 |
| **Claude Code VS Code 2.1.316** | 可编辑独立模板 | 保留此前用户提供的14项请求头和UA，默认不自动补身份正文 |

内置行为固定于已分析的源码，不联网追“最新版”。已有内置或自定义记录不因启动而覆盖。第三条种子可归档，初始版本不能删除，以避免再次初始化后重新出现。

**自动绑定**按最终上游协议解析：Responses→Codex，Messages→Claude Code，Chat/Gemini→普通转发。自动绑定同样固定版本，升级不会悄悄更换规则。

## 新增与修改模板

1. 打开 **模板库 → 新增模板**。
2. 选择 Codex、Claude Code，或已有模板版本作为基线。
3. 填写名称，完整复制为独立草稿。
4. 修改识别、UA、请求头动作、会话、正文规则和读取限制。
5. **保存新版本**。
6. 可先预览／测试，再选择连接和具体版本执行 **应用**。

模板库支持导入JSON文件为新草稿，编辑器可导出脱敏规则副本；导入先校验，不自动保存或应用，自定义普通文本分享前仍需检查。

自定义模板是副本，`basedOn`仅记录来源，不运行时继承。保存v2不会影响仍绑定v1的连接。版本历史支持比较、查看、应用旧版回退；引用中的版本拒绝删除。归档模板不会使已有绑定失效，但不能新应用。

### 请求头规则

每一行可以：
- 覆盖 `set`
- 仅缺失时补充 `set-if-missing`
- 缺失或空值时补充 `set-if-empty`
- 删除 `delete`
- 保留 `preserve`

可以选择始终、原生或第三方条件，并限定操作路径。模板变量只用受支持的真实上下文，例如 `{{session.id}}`、`{{model.id}}`、`{{request.id}}`、`{{client.version}}`；缺少变量时跳过该覆盖，不发未展开字符串。

认证与传输控制头是最终不变量，模板不能设置Authorization、API key、Cookie、Host、Content-Length等。连接凭据在模板处理完成后最后写入。请求头值可能包含用户自行填写的秘密，不要把私密附加值放入准备分享的模板。

### 客户端身份与正文

原生判定只看转换前可见UA，是兼容启发式，不能验证官方客户端。Magpie版本可能把原UA替换为`magpie/...`，此时状态是unknown/third-party，不假称恢复原客户端。

内置Claude模板对非原生Messages请求会补独立system身份块及兼容metadata.user_id；会改变提示前缀、输入token或缓存。内置Codex模板可从client_metadata提升允许的头，并生成按连接／会话隔离的稳定兼容标识。这些行为在模板中可查看、复制后修改或关闭。

宿主真实session通过`chat.headers`携带，不把宿主的私有token发上游。Claude兼容模式会补上缺失的`x-claude-code-session-id`，与已补全的metadata.user_id会话一致；已存在的原生会话头不改写，preserve/off策略不凭空增加。该会话头缺失曾导致Any的Fable 5.2拒绝插件简短请求，0.3.6已按真实对照修复。模板body改写有体积／读取时限和取消支持，不发送超时读取到的半截正文。

### 显式参数

保留 `defaults` → `overrides` → `remove`：补缺、覆盖、最后删除。默认保护模型、消息、工具和stream。Messages保持已有thinking类型切换与interleaved预算兼容。

**`count_tokens` / Gemini `countTokens` 不执行生成参数覆盖或Claude身份正文补全**，即使模板同时声明这些操作。正文参数不执行模板代码或任意脚本。

## 连接与模型

每个连接可配置：
- 名称、地址、启停、认证方式。
- 自动或固定上游协议。
- 手填模型、模型协议覆盖。
- 协议根路径（如 `anthropic: "/anthropic/v1"`）。
- 自动、指定模板版本或普通转发。
- 某模型单独的模板版本覆盖。

连接表单的 **获取模型** 按钮会使用上方当前填写的地址、认证方式、密钥和协议根路径读取模型，新连接无需先保存。成功后可多选模型，**追加选中模型**或**替换为选中模型**；手填列表不会被自动清空。填入只修改草稿，点击保存连接才会持久化。

编辑已有连接时，同一地址留空可复用已存密钥；更换地址需重新填凭据。查询只读模型列表，不发送生成请求、不改变模板绑定或连接版本。失败、取消、空列表均保留手填内容；修改地址、密钥、协议或根路径会使旧结果失效。原生宿主账号仅使用其已绑定且地址匹配的凭据。

**宿主发现的模型与管理页共用发现目录。** 编辑连接时可直接看到同一目标和凭据在过去24小时内发现的模型，显示来源与时间；手填列表仍只由“追加／替换”修改。点击“获取模型”始终发起实时查询。网络失败时可显示同一凭据的历史目录，并明确标记“刷新失败／缓存”；401、403、无效响应和主动取消不会用缓存冒充查询成功。成功空列表会更新目录为空，不恢复旧模型。

从 Magpie 内打开管理页时，模型查询与“模型列表检查”可复用宿主最近15分钟内模型发现的账号网络上下文，包含账号代理；更换目标或凭据不会复用。独立 `node setup.mjs` 进程无法继承 Magpie 的账号代理，只能读取共享目录并使用自身网络。网络错误区分 DNS、连接拒绝、中断、超时、TLS 和 HTTP 状态；页面不显示底层原始错误或密钥。更新到0.3.3后需要重载插件并重新打开管理页，宿主重新获取一次模型后才会产生共享目录；仅刷新旧页面不会替换旧进程代码。

模型级绑定优先于连接默认。模板与最终协议不匹配时拒绝，不静默改用另一模板。测试页显示“已保存的生产上游”；本次测试切换协议不会自动改变生产路由。需要应用时，可明确点击“将本次协议与模板保存为此模型路由”，一次性保存该模型的协议覆盖与精确模板版本，其他模型不变；随后在Magpie重新获取模型或重载插件。

Base URL可填站点根或末尾`/v1`/`/v1beta`；UA PRO去除该末尾版本段后按协议拼接默认路径。自定义apiPaths按协议设置，不能填外域URL、query或路径穿越。远程要求HTTPS，本机回环可HTTP。

凭据模式：
- `api-key`：Messages用x-api-key，Gemini用x-goog-api-key，Responses/Chat用Bearer。
- `bearer`：明确用Bearer，同样填写纯key。
- `custom`：填写完整Authorization值。
- `none`：明确不发送认证。

多个账号可以共用pool `ua-pro`。勾选独立显示并填写siteId后，得到 `ua-pro-<siteId>`；首期最多8个独立站点槽，站点下仍可多账号。站点增删需要重载宿主。连接在独立工具中保存后也需让宿主载入；页面不把文件保存等同于正在运行的宿主生效。

模型默认GET模型列表；手填时不自动查询。固定Gemini协议支持其`models`列表结构和v1beta路径；固定协议/自定义根路径会用于模型查询。协议不明确时，列表使用兼容`/v1/models`。同名模型能力和凭据仍以所选账号为准，插件不做失败后的换key/换模型重试；Magpie自身路由fallback须单独配置。

## 三层测试

| 层次 | 网络与结论 |
|---|---|
| 本地转换预览 | 不联网。使用同一转换函数展示准备发送的脱敏URL、headers、body及规则变化 |
| 连接检查 | 明确确认后读取模型列表，不证明模型回复可用 |
| 实际模型请求 | 明确确认后直测所选连接；普通/流式均支持，可能产生费用；不自动回退 |

测试页会默认选择已启用连接，并自动载入该连接已保存的模型及同凭据的发现目录，优先选中已保存模型；不再填入 `claude-example` 等不存在的 ID。切换连接／模型后，协议与样例正文跟随该连接的配置和模型覆盖；明确手动选定的协议会保留。点击“刷新模型”可更新下拉列表；实际请求模式下没有任何已知模型时会先自动读取一次目录，**不会自动发送生成请求**。离线预览不自动联网，列表为空时禁用生成；“手动输入模型 ID”是可展开的高级选项，模型列表检查仍可单独执行。

**测试协议与模板会联动。** 默认“自动适配本次协议”优先保留兼容的连接绑定；切Messages而原绑定仅支持Responses时，本次明确改用Claude模板，连接生产绑定保持不变。也可选择“严格使用连接绑定”或指定版本；不兼容会前置提示并阻止发送，不在404后暗中改协议或重试。

“本次请求”及确认框显示最终URL、模型、协议与模板；高级选项可仅覆盖本次协议根路径，位于当前连接部署地址下，不接受外域或完整操作路径。填写Base URL或读取模型列表成功不证明上游支持所有协议。测试页是上游直测，不是Magpie客户端协议转换。自定义正文在切模型／协议后保留，不兼容时提供明确的简短样例替换入口。

测试可选当前草稿或已保存版本，执行时固定快照，测试不改绑定。返回连接、模型、测试时间、最终地址、HTTP状态、耗时、首块时间、协议结构、响应文本和上游实际usage。表单改变后旧结果标记为上一次测试。模型列表检查隐藏生成参数并显示实际GET与HTTP；取消和超时分开说明。HTTP200错误JSON或错误SSE不当成功。请求与响应中的已知凭据脱敏，不把host裸key回显到报告。Responses简短测试样例使用数组input、128-token输出上限、store=false与仅用于合成测试的prompt_cache_key；不更改用户明确提供的自定义正文，也不自动修改生产模板。

结果中的“出站请求”说明插件准备/发送了什么，不代表站点确认接收全部字段。预览同连接时使用同凭据作用域生成兼容身份，仍不发网络。

## 保存、应用、回退

```text
编辑草稿 → 保存模板版本 → 预览/测试 → 应用到所选连接或模型
                                             ↓
                             后续新请求固定使用该版本
```

每次保存更新generation，连接引用不可变revision。请求开始时冻结模板、连接和凭据快照；途中编辑不会改变已开始的请求。概览显示宿主实际观察的generation及版本；独立工具看不到另一个进程的内存观察状态，会明确显示等待宿主确认。

保存/应用使用operationId避免重复写入，网络断开后可查询原操作。失败保留草稿，结果未知时锁定重提交。多窗口有revision/generation冲突检查；跨进程不是严格原子CAS。

## 旧 Claude 配置与余额签到

- 旧`claude-code-ua`仍由兼容路径处理，原客户端模型引用继续可用，仍使用原14头和显式参数。
- UA PRO 是唯一连接／模板配置前端，旧Claude编辑器及其HTML／JS／CSS／验证脚本已移除；旧书签仅跳转到UA PRO，不再维护两套页面。旧profile仍可在设置中预览并明确复制为新连接，不删除旧配置或改写原Codex目录。
- 原生旧账号没有自动拷贝key；需要重新在UA PRO连接/登录或继续旧入口。
- New API账号、余额、手动/每日时区签到页面继续保留；站点PAT/Cookie与模型key分开。定时器仅宿主运行时启用，独立设置工具不自动签到。
- 新UA PRO账号余额绑定需要宿主提供明确的账号作用域。旧宿主没有这个接口时，不猜当前账号来写绑定；原有账号管理入口保持原行为。

原生账号key由Magpie保存，UA store只记provider/account引用。每次取host key会核对账号端点；同槽换站后旧连接拒绝使用新key。旧宿主没有account helper时按同provider/key/地址唯一匹配槽位，多个匹配则报错，不任选一个。

## 数据位置

| 文件 | 用途 |
|---|---|
| `runtime/ua-pro.json` | 模板版本、连接、绑定和generation |
| `runtime/ua-pro.json.models.json` | 宿主／管理页共享的模型发现目录：模型、来源、时间和作用域摘要，不含key |
| `runtime/profile.json` | 原Claude独立配置，兼容保留 |
| `runtime/accounts.json` | New API站点账号 |
| `runtime/schedule-claims/` | 每日签到防重复记录 |
| `runtime/scratch/` | 测试临时文件，验证后清理 |

`uaFile`插件选项或环境变量`UA_PRO_FILE`指定UA状态文件绝对路径。`profileFile`/`MAGPIE_CLAUDE_PROFILE_FILE`继续用于旧配置。独立工具`--config`指定旧profile路径，默认UA状态放同目录的ua-pro.json，也可用UA_PRO_FILE覆盖。宿主与独立工具必须使用同一个UA文件。

连接凭据文件以文件权限保护的明文保存，不是加密保险库；POSIX0600/0700，Windows依赖NTFS ACL。不要将runtime目录放入公开仓库。新建/启停/更新不会自动访问所有连接做推理。
