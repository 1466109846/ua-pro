# UA PRO

Magpie 的出站客户端兼容插件。将 **Codex / Claude Code 请求规则**保存为版本化模板，按连接或模型应用，支持 Responses、Anthropic Messages、Chat Completions 和 Gemini。

当前版本 **0.3.6**，npm 包名 [`opencode-claude-code-ua`](https://www.npmjs.com/package/opencode-claude-code-ua)，主供应商 ID 为 `ua-pro`。无 npm 运行依赖。

## 安装与打开管理页

在 Magpie「插件 → 添加插件」填写 npm 来源：

```text
opencode-claude-code-ua@0.3.6
```

也可以使用终端：

```sh
magpie plugin add "opencode-claude-code-ua@0.3.6"
magpie plugin login ua-pro
```

登录方式中选择 **打开 UA PRO 管理**。已经登录账号后，也可再次执行登录命令打开管理页，管理其他连接和模板。插件内嵌日芒 SVG 图标，无需联网加载图片；界面支持纯白、纯黑及跟随系统主题。

如需使用 GitHub 来源：

```sh
magpie plugin add "github:1466109846/ua-pro"
```

同一插件请选择一种安装来源，不要重复安装。安装或更新不会自动迁移其他插件的配置。

### 独立运行管理页

需要 Node.js 22 或以上。下载仓库或 Release 后，在插件目录运行：

```sh
node setup.mjs
```

打开终端输出的一次性回环链接。服务仅监听本机，不默认监听公网。独立工具保存连接后，需要在 Magpie 重载插件；宿主与独立工具应指向同一个 UA 状态文件。

## 快速配置

1. 打开 **连接 → 新增连接**，填写名称、上游 Base URL、认证方式和 API key。
2. 点击 **获取模型**，按当前表单中的地址和凭据查询；新连接无需先保存。
3. 多选模型，选择 **追加选中模型**或**替换为选中模型**，然后保存连接。
4. 选择自动模板，或指定一个已保存的模板版本。
5. 在测试页检查最终地址、模型、协议和模板，再确认发送请求。
6. 在 Magpie 重新获取模型或重载插件，让宿主载入保存的连接和路由。

客户端连接的是 **Magpie 本地网关**，使用 Magpie 网关密钥，而不是直接填写上游 key。模型引用请从测试页复制：

- 主池：`ua-pro/<模型 ID>`。
- 独立站点：`ua-pro-<siteId>/<模型 ID>`。

独立站点的模型不能写成主池引用。客户端协议转换由 Magpie 负责；UA PRO 接收转换后的请求，执行对应出站模板并使用所选账号凭据。

## 连接与模型

每个连接支持启停、自动或固定上游协议、模型列表、模型级协议覆盖、协议根路径，以及连接级和模型级模板绑定。

Base URL 可填写站点根地址，或以 `/v1`、`/v1beta` 结尾的地址。插件去除末尾版本段，再按协议拼接路径；自定义根路径可以保留部署前缀，例如 `anthropic: "/anthropic/v1"`。不能填写外域 URL、查询参数或路径穿越。远程地址要求 HTTPS，本机回环可使用 HTTP。

| 认证方式 | 发送方式 |
|---|---|
| `api-key` | Messages 使用 `x-api-key`，Gemini 使用 `x-goog-api-key`，Responses / Chat 使用 Bearer |
| `bearer` | 始终使用 Bearer，填写纯 key |
| `custom` | 填写完整 Authorization 值 |
| `none` | 不发送认证 |

编辑已保存连接时，同一地址留空 key 可以复用原密钥；更换地址需要重新填写凭据。原生 Magpie 账号的 key 由宿主保存，UA PRO 仅记录账号引用，并核对账号端点；同一账号槽换站后，旧连接不能使用新站点凭据。

模型查询只读取列表，不发送生成请求、不改变模板绑定，也不会清空手填模型。追加／替换只修改表单草稿，保存后才持久化。失败、取消和空列表都会保留手填内容；目标或凭据变更会使旧查询结果失效。

宿主与管理页共用按目标和凭据隔离的模型发现目录，显示来源和时间。点击 **获取模型**始终尝试实时查询；网络失败时可显示过去 24 小时的同作用域目录，并标明缓存及失败原因。401、403、无效响应或主动取消不会用缓存冒充成功，成功的空列表会替换旧目录。

默认多个账号共用 `ua-pro` 主池。勾选独立显示并填写 `siteId` 后，供应商为 `ua-pro-<siteId>`；最多 8 个独立站点槽，每个站点可有多个账号。站点增删需要重载宿主。

### 生产路由与测试路由

模型级协议和模板绑定优先于连接默认配置。自动协议按模型名推断，不代表上游已经支持该接口；明确知道端点类型时，应保存固定协议或模型覆盖。

测试页会显示 **已保存的生产上游**。仅切换测试协议不会修改生产配置。如需应用，可点击 **将本次协议与模板保存为此模型路由**，一次性保存该模型的协议和精确模板版本，其他模型保持不变；随后在 Magpie 重新获取模型或重载插件。

插件不在失败后自动更换 key、模型或协议。Magpie 自身的路由与 fallback 需单独配置。

## 模板与版本

首次加载建立三份初始模板，已有记录不会因启动而被覆盖：

| 模板 | 类型 | 默认行为 |
|---|---|---|
| Codex | 内置只读 | Responses 请求头、元数据及会话兼容；固定基线版本 0.159.0 |
| Claude Code | 内置只读 | Messages 请求头、条件性 system / user_id 补全及 fast beta 联动；固定 CLI 基线 2.1.296 |
| Claude Code VS Code 2.1.316 | 可编辑独立模板 | 固定 UA 和 14 项请求头，默认不补客户端身份正文 |

内置基线不自动联网追踪新版本。自动绑定按最终上游协议选择：Responses → Codex，Messages → Claude Code，Chat / Gemini → 普通转发；绑定仍锁定具体模板版本。

### 新增、保存与应用

1. 在 **模板库 → 新增模板**选择内置或已有模板版本作为基线。
2. 完整复制为独立草稿，修改名称、UA、请求头、会话或正文规则。
3. **保存新版本**，先预览或测试，再 **应用**到连接或模型。

自定义模板是完整副本，不在运行时继承原模板。保存 v2 不影响仍绑定 v1 的连接。版本历史支持比较、查看和回退；被引用的版本不能删除。归档不会使已有绑定失效，但不能新应用归档模板。

JSON 导入只建立经校验的草稿，不自动保存或应用；导出为脱敏规则副本。自定义普通文本和附加请求头分享前仍需人工检查。

### 请求头与参数规则

请求头支持 `set`、`set-if-missing`、`set-if-empty`、`delete`、`preserve`，可限定条件和操作路径。模板变量仅使用支持的上下文，例如 `{{session.id}}`、`{{model.id}}`、`{{request.id}}`、`{{client.version}}`；缺少变量时跳过覆盖，不发送未展开的字符串。

认证最后写入。模板不能覆盖 Authorization、API key、Cookie、Host、Content-Length 等认证或传输控制头。模板使用声明式规则，不执行用户脚本。

参数按 **`defaults` → `overrides` → `remove`**处理：补缺、显式覆盖、最后删除。默认保护模型、消息、工具和流式选择。`count_tokens` / Gemini `countTokens` 不执行生成参数覆盖或 Claude 身份正文补全。

### 正文与会话兼容

客户端原生判定仅基于转换前可见 UA，是启发式，不验证官方客户端。宿主可能将原 UA 替换为 `magpie/...`，插件不会假称能够恢复它。

内置 Claude 模板对非原生 Messages 请求可补 system 身份块及兼容 `metadata.user_id`，并补缺失的 `x-claude-code-session-id`，保持会话一致。已有原生会话头不改写，`preserve` / `off` 策略不会凭空新增。Codex 模板可提升允许的 `client_metadata` 头，并生成按连接和会话隔离的兼容标识。

这些显式兼容规则可能改变提示前缀、输入 token 或缓存；可复制模板后查看、修改或关闭。正文读取有体积、时限和取消保护，原生已有账单字段不伪造或替换。

## 三层测试

| 测试 | 网络行为与结论 |
|---|---|
| 本地转换预览 | 不联网，展示同一转换函数准备的脱敏 URL、headers、body 和规则变化 |
| 模型列表检查 | 明确确认后读取目录，不证明模型能够生成回复 |
| 实际模型请求 | 明确确认后直测所选连接，支持普通／流式，可能产生费用，不自动回退 |

测试页自动载入已保存模型及同凭据的发现目录，优先选择已保存模型。实际请求模式下没有已知模型时，会先读取一次目录，但 **不会自动发送生成请求**；离线预览不自动联网。也可展开高级选项手动填写真实模型 ID。

默认 **自动适配本次协议**会保留兼容的连接绑定；绑定不兼容时，本次明确选用相应内置模板，生产绑定不变。选择严格绑定或指定版本时，不兼容会在发送前阻止请求。

确认框显示最终 URL、模型、协议和模板。高级根路径覆盖只用于本次测试，不修改连接。自定义正文在切换协议或模型后保留，结构不兼容时需明确替换为样例。

结果显示连接、模型、测试时间、HTTP 状态、耗时、首块时间、响应和上游 usage。表单变化后，旧结果标为过期；HTTP 200 中的错误 JSON 或错误 SSE 不算成功，取消和超时分别说明。测试不修改绑定；出站预览不代表站点确认接收了所有字段。

## 保存、应用与回退

```text
编辑草稿 → 保存模板版本 → 预览／测试 → 应用到连接或模型
```

请求开始时冻结模板、连接和凭据快照，在途请求不随编辑改变。保存与应用分离；保存文件不等于正在运行的宿主已载入。独立工具无法观察另一进程的运行状态，会显示等待宿主确认。

写操作使用 operationId 防止重复提交，网络断开后可查询原操作。失败保留草稿，结果未知时阻止盲目重提；多窗口有 revision / generation 冲突检查，跨进程不提供严格原子 CAS。

## 兼容入口与 New API

旧 `claude-code-ua` 供应商保留兼容，原模型引用仍可使用。UA PRO 是唯一连接／模板管理前端，旧书签跳转到统一页面。设置中可预览旧 profile 并明确复制为新连接，不自动删除旧配置或复制原生账号 key。

New API 账号管理、余额查询、手动签到和按 IANA 时区的每日签到保留。站点 PAT / Cookie 与模型 key 分开；定时器仅宿主运行时启用，独立工具不自动签到。余额绑定依赖宿主明确提供账号作用域，旧宿主不支持时不会猜测账号。

## 数据与安全

| 默认文件 | 用途 |
|---|---|
| `runtime/ua-pro.json` | 模板、连接、绑定、generation 及本地保存的连接凭据 |
| `runtime/ua-pro.json.models.json` | 模型发现目录、来源、时间和作用域摘要，不含 key |
| `runtime/profile.json` | 旧 Claude 配置，兼容保留 |
| `runtime/accounts.json` | New API 站点账号 |
| `runtime/schedule-claims/` | 每日签到防重复记录 |

`uaFile` 插件选项或 `UA_PRO_FILE` 环境变量可指定 UA 状态文件绝对路径。`profileFile` / `MAGPIE_CLAUDE_PROFILE_FILE` 指定旧配置；独立工具的 `--config` 指定旧 profile 路径，默认 UA 文件放在同目录，也可由 `UA_PRO_FILE` 覆盖。

本地凭据以文件权限保护的明文保存，不是加密保险库。POSIX 使用 0600 / 0700，Windows 依赖 NTFS ACL。不要分享或提交 runtime、配置副本或附加秘密请求头。npm 包仅包含运行代码、图标、README 和必要许可证，不含用户数据或开发测试。

仅连接自己拥有或已获授权的 API。UA 和兼容标识不证明官方客户端身份，不提供 OAuth、设备认证、签名或额外账户权限，也不能保证任意上游接受请求。

## 常见问题

**管理页如何再次打开？**

执行 `magpie plugin login ua-pro`，选择 **打开 UA PRO 管理**。管理会话过期后需重新打开；刷新旧页面不能延长授权。

**宿主能获取模型，独立管理工具却失败？**

从 Magpie 打开管理页后，查询可复用最近 15 分钟同目标／凭据模型发现的账号网络上下文，包括账号代理。独立 Node 进程不能继承 Magpie 账号代理，需要自行配置网络；支持的 Node 版本可显式使用环境代理。插件不硬编码本地代理端口，也没有独立代理设置面板。

**模型列表成功，但生成返回 404？**

确认生产模型路由、实际协议根路径，以及独立站点的供应商前缀。目录成功不代表所有生成端点可用；测试页直测上游，客户端到上游的协议转换由 Magpie 根据已保存路由完成。

**修改后为什么没有生效？**

模板先保存，再应用；连接、站点或模型协议更新后，在 Magpie 重新获取模型或重载插件，并重新打开管理页。不要将文件保存或单次测试成功当作生产生效证明。
